# 2026-09-09 재검토 후 조치

재검토에서 확인한 7가지 문제를 수정했다. 파생 구간 파일의 내용은 유지했으며, 실행 중인 Reader를 새 코드로 재기동하고 기존 로컬 AI 서버와의 연결을 확인했다.

| 항목 | 조치 | 검증 |
|---|---|---|
| 원문 누락 시 불완전한 재구축 | 등록된 원문의 존재를 재구축 전에 검사한다. 키르케고르·비트겐슈타인 구간 빌더는 누락·빈 결과를 건너뛰지 않고 실패한다. 전체 재구축은 이전 산출물을 임시 보관하고 실패·Ctrl+C 시 복구한다. | 원문 하나가 빠진 두 작품의 기존 구간 파일 보존, 중간 실패·중단 시 바이트와 수정 시각 복원 |
| 판본 오연결 | 노트·번역·학습 기록의 조회와 내보내기에 정확한 판본 필터를 적용한다. 학습 기록은 판본을 포함한 원문 URL로 이동한다. URL 처리에는 화면 글자 정리 함수를 사용하지 않아 `#` 앵커를 보존한다. | 본문 페이지에서 주석 기록 클릭 시 실제 주석 판본으로 이동하고 해당 판본으로 번역 요청 |
| 확정본과 모델 캐시의 결합 | 같은 원문 문장·판본에 대한 가장 최근 사람 검토 기록을 모델 프롬프트·캐시 검사 전에 조회한다. 명시적 재생성은 허용하고 이전 확정 기록을 보존한다. | 프롬프트와 파이프라인 변경 후에도 모델·프롬프트 호출 없이 확정본 반환, 원문·판본이 다르면 재사용 차단 |

| 늦은 요약·노트 응답 | 번역 요약·학습 기록 요약·노트 목록이 최신 요청과 현재 조회 조건을 확인하고 결과를 적용한다. 오래된 실패 응답도 현재 화면을 지우지 않는다. | 응답 순서를 역전시켜도 최신 검토 상태와 현재 노트 필터 유지 |
| 부정확한 준비 상태 | 오프셋 인덱스의 스키마·코퍼스 범위·원문 파일 시그니처를 제한된 조회로 확인한다. 핵심 기능 준비와 모델 준비를 구분하고 CLI와 런처에 반영한다. | 인덱스 누락·오래된 시그니처 감지, 핵심 데이터 장애에서 CLI 실패, 운영 서비스의 모든 준비 상태 정상 |

새 동작은 기존 원문과 구간 ID의 재번호화를 요구하지 않는다. 정적 JavaScript URL 버전도 올려 이전 캐시와 새 동작의 혼용을 줄였다.

## 검증

- Python 회귀 검사 24개와 실제 JavaScript 함수의 비동기·판본 이동 검사를 통과했다.
- 원문 없는 환경의 source-light 검사 묶음, API·서버 경계·노트·AI 기록·문장 번역 계약 검사를 통과했다.
- 실제 원문 대상 조회, 등록 원문 사전 검사, 키르케고르·비트겐슈타인 구간 파일의 최신성 검사를 통과했다. 구간 파일 재생성은 필요하지 않았다.
- 정적 경로 검사와 기존 읽기 상호작용 브라우저 검사를 통과했다.
- 폭 1,365px·390px의 실제 브라우저에서 확정본 조회, 다른 판본의 원문 열기, 색인의 비번역 처리를 모두 확인했다. 이 검증에서는 모델 생성이 실행되면 실패하도록 막았다.
- 검색 평가는 48/48, MRR 0.9896이다. 고정 번역 오류 사례 9개의 오프라인 검사와 엄격한 사람 평가 게이트도 통과했다.
- 재기동 후 운영 Reader의 `reader_ready`, `translation_ready`, `source_index.ready`를 확인했고, 니체의 새 확정 기록이 모델 생성 없이 조회되는 것을 확인했다.

## 운영상 한계

진행 중인 llama.cpp HTTP 호출 자체의 즉시 중단은 보장하지 않는다. 취소 후 추가 단계와 저장을 막고 다음 요청이 종료를 기다리도록 처리했다. 무관한 동시 생성과 추가 대기 요청은 여전히 제한한다.

전체 재구축은 산출물을 개별 교체하므로 유지보수 시간에 실행해야 한다. 예외와 Ctrl+C는 자동 복구하지만 강제 프로세스 종료·전원 중단은 자동 복구 코드를 실행할 수 없다. 남은 `data/.rebuild-backup-*`를 복구용으로 보관해야 하며 이 디렉터리는 Git에서 제외된다. 임시 백업을 위한 추가 디스크 공간이 필요하다.

새 모델 번역 생성, 실제 서비스 강제 종료 복구 시험, 원격 CI 실행, 자동 시작 작업 등록, 커밋·푸시는 이번 작업에 포함하지 않았다.
