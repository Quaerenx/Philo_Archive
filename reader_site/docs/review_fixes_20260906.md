# 2026-09-06 검토 후 개선

본문 누락, 기록 보존, 문장 연결, 비동기 요청, 검색 및 수집 실패 처리를 수정했다. 실제 노트와 번역 JSONL은 이전 내용을 유지한다.

- 키르케고르의 JSON 발췌가 있으면 기존 추출 결과를 유지한다. 발췌가 없으면 같은 문서의 로컬 SKS HTML을 공통 추출기로 읽고 메타데이터와 구간의 출처도 실제 HTML로 기록한다. 페이지 메뉴·스크립트·주석 팝업은 본문에 포함하지 않는다. 빈 자료는 구간 빌더와 스키마 검사가 차단한다. 구분 번호만 있는 자료는 `reading_status: labels_only`로 명시하고 안내와 참조 앵커를 표시하며 문장 번역을 허용하지 않는다.
- 약어와 이름의 이니셜 조각을 합치되 뒤쪽 문장의 기존 ID를 재번호화하지 않는다. 합쳐진 조각의 이전 ID는 HTML 앵커 별칭과 문장 API에서 같은 원문 위치로 해석된다. 이전 번역은 당시 원문과 해시를 보존하며, 현재 문장 해시가 다른 기록을 현재 문장의 학습 완료 상태로 계산하지 않는다. 판본 사이의 같은 문장 ID도 구분한다.
- 구간 오프셋 DB의 파생 스키마 버전은 3이다. 문장 수 계산이 바뀌었으므로 코드를 갱신한 뒤 `python scripts/build_segment_offset_index.py` 또는 전체 재구축이 필요하다. 원문·노트·번역 파일의 스키마를 강제로 이전하지 않는다.
- 번역 JSONL에 손상된 줄 또는 객체가 아닌 줄이 있으면 읽기·쓰기를 명시적으로 실패시킨다. 원본 파일을 백업한 후 복구해야 하며 정상 줄만 골라 덮어쓰지 않는다.
- 번역 생성과 검토 응답은 요청 당시 대상과 현재 선택이 일치할 때 상세 화면에 적용한다. 수정된 정적 스크립트 URL 버전을 올려 이전 캐시와 혼용되지 않게 했다.
- 번역 POST에 선택적으로 UUID `request_id`를 보낼 수 있다. `/api/sentence-translation/cancel`에 같은 ID를 POST하면 후속 모델 단계와 결과 저장을 중단한다. 취소가 먼저 도착한 경우도 기억하고, 이미 저장이 완료됐으면 `cancelled: false`를 반환한다. 모델 작업은 한 번에 하나로 제한하며 겹치는 작업은 409로 응답한다. 클라이언트 연결 종료도 단계 경계와 저장 전에 확인한다. 이미 진행 중인 llama.cpp 호출 자체가 즉시 끝나는 것은 보장하지 않으며, 반환된 결과를 취소 후 저장하지 않는다.
- 쓰기 API는 같은 Origin, 허용된 로컬 Host와 포트, JSON Content-Type을 검증한다. Origin 없는 로컬 스크립트의 JSON 요청은 지원하지만 교차 출처 브라우저 쓰기는 거부한다. DELETE에도 출처 검사를 적용한다.
- 번역·비평·수정 시스템 지시문과 chat-template 옵션을 요청 해시에 포함한다. 비트겐슈타인의 혼합 언어를 일괄 독일어로 기록하지 않으며 제공된 구체적인 언어 정보가 있으면 우선한다.
- Markdown 링크 제거 함수를 화면과 구간 빌더가 공유하고 인용문에도 색인과 같은 앵커를 출력한다. 검색 DB는 실제 일치 문맥을 만들 수 있도록 원문을 보관한다. 임시 DB의 SQLite·FTS 무결성과 행 수를 확인하고 동기화한 뒤 원자적으로 교체한다. 실패하면 이전 DB를 보존한다.
- 구간 제목과 현재 메타데이터의 일치를 검사한다. 키르케고르의 모든 등록 판본에 구간이 있고 해당 구간 종류가 본문 유무 상태와 일치하는지도 검사한다.
- Git에서 제외된 두 니체 수집기에서는 파일 존재만으로 작품 수집 완료를 판단하지 않는다. 출력 해시가 맞는 완료 manifest가 필요하며, 하위 페이지가 실패하면 실패 목록을 남기고 이전 출력은 보존한다. 다음 실행에서 미완료 작품을 재시도한다. 수집기를 다시 실행하거나 원격 원문을 변경하지는 않았다.

새 회귀 검사는 `python scripts/check_review_regressions.py`로 실행한다. 임시 저장소와 모의 모델을 사용해 손상 데이터, 약어와 이전 링크, 잘못된 HTTP 출처, 지연 응답, 취소·연결 종료, 검색 DB 빌드 실패, 부분 수집 재개를 검증한다. 로컬 수집기가 없는 clean clone에서는 해당 오프라인 수집기 검사만 건너뛴다. Node.js가 있으면 실제 브라우저 함수의 비동기 경합 검사도 실행한다. 이 검사는 source-light 검사와 전체 재구축 검사에 포함된다.

번역 품질의 사람 판정은 코드 검사와 구분한다. `Reader Translation Release Quality` 수동 워크플로가 엄격한 goldset 게이트를 실행한다. 기존 니체 평가의 미달 점수는 새 사람 평가 없이 변경하지 않았다.

## 적용 결과

- 비어 있던 키르케고르 기본 페이지 124개 중 123개에서 본문을 복구했다. `p259`는 수집된 HTML과 PDF에도 구분 번호 세 개만 있어 본문 없음으로 표시한다. 전체 211개 기본 페이지는 본문 210개·구분 번호만 있는 자료 1개이며, 전체 630개 판본은 본문 629개·구분 번호만 있는 자료 1개다.
- 키르케고르 구간은 25,359개에서 86,629개로 늘었다. 기존 25,359개와 비트겐슈타인 125,676개의 구간 ID와 본문은 모두 유지했다. 전체 검색 구간은 286,712개다.
- 니체 33개 작품의 14,227개 구간과 키르케고르 211개 기본 페이지의 57,912개 구간을 실제 HTML과 대조했으며 누락 앵커와 본문 불일치는 없었다.
- 번역 169건과 노트 파일을 포함한 개인 기록 파일 5개의 바이트와 해시가 작업 전 백업과 일치한다. 번역 169건의 대상은 모두 해석 가능하다. 그중 약어 병합으로 현재 문장 내용이 달라진 9건은 당시 기록을 유지하고, 병합된 조각의 이전 ID 4개도 별칭으로 해석한다.
- 검색 DB에 문맥 생성용 본문 전체를 보관하므로 로컬 SQLite 크기는 약 530 MiB에서 869 MiB로 증가했다. 검색 결과의 표시 분량은 계속 제한한다. 동일 본문이 여러 판본에 있으면 제목 길이 차이만으로 순위가 달라지지 않도록 정렬을 안정화했다.
- 기존 번역의 캐시를 일괄 삭제하지 않는다. 시스템 지시문과 요청 옵션을 포함한 새 해시 기준을 충족하지 않는 기록은 다음 생성 요청에서 새 결과가 만들어질 수 있으며 이전 기록은 남는다.

## 검증과 남은 범위

새 Python 회귀 검사 15개와 Node.js 비동기 검사를 통과했다. 스키마, 구간 오프셋, 문장·출처 연결, 검색 API와 데이터 무결성 검사도 통과했다. 검색 평가는 48/48개를 통과했으며 MRR은 0.9896, R@1은 0.9792다. 정적 경로, 25개 화면의 HTML 검사와 데스크톱·모바일 크기의 실제 브라우저 읽기 상호작용 검사도 통과했다.

원문 루트를 빈 임시 폴더로 지정한 source-light 검사 묶음도 통과했다. 복구된 `aa` 페이지와 본문 없음 상태인 `p259`는 폭 1,365px·390px의 실제 브라우저에서 확인했다. `aa`의 문장 1,129개가 표시되고 `p259`는 참조 앵커 세 개와 안내만 표시했으며, 두 크기 모두 JavaScript 오류와 가로 넘침은 없었다. GitHub Actions 자체는 아직 원격에서 실행하지 않았으며, 워크플로가 호출하는 검사 명령은 로컬에서 검증했다.

엄격한 사람 번역 품질 게이트는 4개 중 3개 통과, 1개 미달이다. 미달 항목은 `nietzsche-gm-p-0004-s001`의 충실도와 한국어 가독성이며 재평가가 필요하다. 실제 모델을 호출해 새 번역을 생성하거나 원문을 재수집하지 않았다. 취소 검증은 임시 기록 저장소와 모의 모델을 연결한 HTTP 요청으로 수행했다. 변경 전 파생 데이터와 개인 기록은 별도 로컬 백업에 보관했고, 커밋·푸시·배포는 수행하지 않았다.
