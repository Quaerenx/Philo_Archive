## 번역 비교

기존 모델 번역과 사람이 확정한 번역을 그대로 읽어 비교한다. 아직 확정하지 않은 경우와 두 번역이 같은 경우를 명시한다. 변경 표현에는 색뿐 아니라 밑줄을 적용한다. 목록의 공간이 충분하면 두 번역을 나란히 표시하고, 좁은 패널과 모바일에서는 세로로 배치한다.

긴 텍스트에서 비교 계산량이 160,000 토큰 쌍을 넘으면 강조를 생략하고 양쪽의 전체 내용을 표시한다. 번역·평가 이력은 변경하지 않는다.

## 읽기 설정

기본, 원문 집중, 번역 비교 프리셋을 제공한다. 개별 설정은 글자 16/18/21px, 줄 간격 1.75/2/2.25, 본문 최대 폭 48/64/76ch, 데스크톱 패널 폭 360/440/520px이다. 실제 본문 폭은 화면과 패널의 사용 가능한 공간 안에서 제한된다. 모바일은 기존 패널 방식으로 표시한다.

설정은 `philo.reader.readingPreferences.v1` 키로 현재 브라우저에 저장한다. 잘못된 값은 기본값으로 되돌리고, 저장소를 사용할 수 없으면 현재 화면에 적용한 뒤 저장 불가를 알린다. 기존 읽기/학습 모드와 노트 초안 기능은 유지한다.

## 용어·표현 설명의 범위

다음 자료만 사용하며 추가 모델 요청으로 설명을 생성하지 않는다.

- 작품·판본에 맞는 사람 승인 용어: `translation_profiles.json`의 승인 프로필.
- 등록된 작품 개념: 기존 개념 목록의 검색어와 한국어 설명. 승인 용어와 구별해 표시한다.
- 현재 확정 번역의 번역 노트 또는 자동 검토된 번역 노트: 서버가 현재 원문·번역에 연결해 공개한 노트.

현재 원문과 다른 노트, 검토가 필요한 노트, 원문에 없는 표현은 제외한다. 전체 책을 다시 가공하지 않고 선택한 문장에만 버튼을 붙인다. 원문 텍스트는 유지한다. 클릭하면 설명을 표시하고, 닫기 또는 Escape로 닫으며 초점을 원래 버튼으로 돌린다. 설명을 열 때 번역 요청을 추가하지 않는다. `이 작품에서 더 찾기`는 읽던 위치로 돌아오는 링크를 포함한다.

용어를 Reader HTML의 JSON에 넣을 때 `<`, `>`, `&`를 JSON 유니코드 이스케이프로 보존한다. 특수문자가 용어 검색을 깨뜨리거나 HTML로 해석되지 않도록 검사한다.

## 검증

- JavaScript 동작 검사 11항목: 한국어·구두점 차이, HTML 이스케이프, 긴 문장, 미확정 표시, 설정·저장 실패, 용어 경계, 원문·노트 연결과 출처.
- Python 검사 3개: 작품·판본별 승인 용어 범위, JSON 특수문자 보존, 등록 개념 속성 이스케이프. 기본 검사에 포함했다.
- 변경 JavaScript 8개 문법 검사, 기존 비동기 검사, 전체 기본 검사, `git diff --check` 통과.
- 로컬 HTTP에서 4개 corpus의 6개 작품 페이지와 새 자산 6개가 정상 응답함을 확인했다. 승인 용어가 실제로 등록된 두 작품도 포함한다.
- 실제 브라우저에서 1280px와 390px 화면을 확인했다. 비교 펼치기, 설정 변경·새로고침 유지, 승인 용어·확정 노트 설명, Escape 닫기, 필터 배치를 검증했다. 확인한 화면에서 가로 넘침과 콘솔 오류가 없었다.
- 비교 안내·강조·상태·번역 본문 6종의 실제 대비를 측정했다. 모두 7.46:1 이상이었다. 전체 페이지의 접근성 인증을 의미하지는 않는다.
- 기존 운영 번역·노트·승인 프로필·골드셋·원문 검사 규칙·최신 평가 장부 등 보호 파일 9개의 SHA-256을 확인했다. 모두 변경되지 않았다.

전체 기본 검사 중 기존 가져오기 테스트가 한 번 `import_failed_rolled_back`으로 실패했다. 원인은 확인되지 않았다. 해당 항목의 단독 검사와 전체 기본 검사 재실행은 모두 통과했고, 가져오기 구현이나 테스트는 수정하지 않았다. 첫 실패 로그와 최종 통과 로그를 모두 보존했다.

장시간 사용, 실제 터치 기기, 모든 책·설정 조합은 검증하지 않았다. 새 모델 번역의 품질 평가는 이번 UI 작업 범위에 포함하지 않았다.
