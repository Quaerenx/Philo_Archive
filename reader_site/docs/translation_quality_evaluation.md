# 번역 품질 인간 평가

`data/translation_quality_goldset.json`은 네 코퍼스를 모두 포함하는 사람 평가 표본이다. 2026-09-09 확장 후 총 20건이며 현재 모두 평가 완료다. 2026-09-30 LSHD의 최종 v8 후보 K02·N01·W03 재평가를 반영해 모델 후보 20건 모두 합격이다. 이전 후보와 평가자는 `evaluation_history`에 보존한다. 이후 새 항목을 추가하면 사람이 원문과 후보 번역을 검토하기 전까지 `pending`으로 유지하며 골드 번역이나 품질 합격으로 계산하지 않는다. 최신 평가 집계는 검사 명령과 이 문서의 후속 평가 기록에서 확인한다.

평가자는 각 항목에 다음 정보를 기록한다.

1. `reference_translation`: 사람이 직접 교정하고 확정한 번역
2. `human_evaluation.status`: `evaluated`
3. `evaluator`: 평가자를 구분할 수 있는 이름 또는 내부 식별자
4. `evaluated_at`: 시간대가 포함된 ISO 8601 시각
5. `scores`: 충실성, 완전성, 용어, 한국어 가독성의 1점부터 5점까지 정수 점수
6. `notes`: 판정 근거와 주요 오류

구조와 코퍼스 범위는 다음 명령으로 검사한다.

```powershell
python .\scripts\check_translation_goldset.py
```

모든 항목의 실제 인간 평가가 끝났는지는 엄격 모드로 검사한다. `pending` 항목이 하나라도 있으면 실패한다.

```powershell
python .\scripts\check_translation_goldset.py --require-complete
```

릴리스 품질 게이트는 다음 명령을 사용한다. 이 모드는 `pending` 항목뿐 아니라 평가된 네 차원 중 하나라도 `passing_score_per_dimension`보다 낮은 항목을 모두 차단하며, 실패 메시지에 항목 ID와 미달 차원을 표시한다.

```powershell
python .\scripts\check_translation_goldset.py --require-passing
```

## Wittgenstein `term` 문맥 조사와 판정

`wittgenstein-10-7-10-p-0001-s001`은 평가자가 `term`의 의미를 확정할 문맥이 부족해 보류한 항목이다. 동일 기록의 바로 다음 설명은 파일명 `Lent30a01r` 가운데 `Lent30a`가 “the first set of summaries of the Lent 1930 notes”를 뜻한다고 밝힌다. 따라서 이 문장의 `term`은 일반적인 “용어”가 아니라 대학의 “학기”이다.

LSCD는 이 문맥 근거를 검토한 뒤 `term`을 “학기”로 확정했다. 확정 번역은 다음과 같다.

> 아카이브 주석 F: 각 노트 페이지가 어느 학기에 해당하는지에 관한 정보는 각 팩시밀리 파일명의 일부로 체계적으로 제공된다.

`term`을 “용어”로 옮긴 2026-09-04 후보는 충실성 3, 완전성 5, 용어 정확성 2, 한국어 가독성 4로 평가되어 합격 기준에 미달했다. 자동 비평은 이 후보를 통과시켰지만 인간 판정은 핵심 전문 용어의 오역을 확인했으므로, 인간 판정을 우선해 문장 한정 승인 규칙과 영구 회귀 표본에 반영한다.

## 2026-09-04 LSCD 재평가 결과

- 키르케고르 재생성 후보: 4/5/4/4로 합격. 다만 `thi`의 인과관계와 `overgivet`의 내맡겨지는 의미를 다음 생성에 더 명확히 보존하도록 승인 지침을 보강했다.
- 니체 재생성 후보: 3/5/4/3으로 미달. `wir selbst uns selbst`를 별개의 술어로 반복한 오류를 문장 한정 금지 규칙과 회귀 표본으로 추가했다.
- 비트겐슈타인 재생성 후보: 3/5/2/4로 미달. `term`을 “용어”로 처리한 오류를 문장 한정 승인 규칙과 회귀 표본으로 추가했다.

이 평가로 네 초기 표본 모두 인간 평가가 완료되었다. 다만 완료 상태와 품질 합격 상태는 별개이며, 미달 후보를 개선해 새로 생성하더라도 평가자가 다시 점수를 제출하기 전에는 기존 인간 판정을 자동으로 덮어쓰지 않는다.

비트겐슈타인 v4 재생성 후보는 후속 평가에서 5/5/5/4로 합격했다. `term`의 “학기” 의미와 모든 의미 요소가 보존되었고, 사람 확정본은 번역투를 줄이기 위해 “어느 학기에 해당하는지”, “파일명의 일부로 체계적으로 제공된다”로 다듬었다. 현재 골드셋은 4건 중 3건이 차원별 합격 기준을 충족하며, 남은 미달 항목은 니체 1건이다.

니체 후속 개선에서는 수정 단계가 `unbekannt`를 삭제하거나 뒤의 재귀 강조에 잘못 연결하는 실패를 문장별 필수 의미 규칙으로 고정했다. 또한 모델 비평이 놓친 문장 끝 콜론을 결정적으로 검사하고, 완전한 사람 승인 구절이 실제 번역에 있을 때 그 일부에 대한 형식 오탐만 제한적으로 억제하도록 품질 파이프라인을 v6으로 갱신했다. v6 후보 “우리 인식하는 자들은 우리 자신에게 미지이며, 우리 스스로가 우리 자신에게 그러하다:”는 자동 수정 후 비평을 통과했지만, 골드셋의 인간 점수는 재평가 전까지 기존 미달 판정을 유지한다.

번역 파이프라인을 바꾼 뒤 생성한 비교 번역은 새 인간 평가의 입력일 뿐 기존 점수를 자동으로 대체하지 않는다. 특히 모델 비평의 `critic_pass`는 사람의 네 차원 합격 판정과 동일하지 않다. 개선 번역은 평가자가 다시 점수를 제출한 뒤에만 골드셋 후보와 점수를 갱신한다.

모델 출력이나 자동 비평 결과를 사람 평가처럼 입력해서는 안 된다. 표본을 늘릴 때는 코퍼스별 시대, 장르, 문장 길이, 난도와 고유 용어가 한쪽으로 치우치지 않게 확장한다.

2026-09-06부터 GitHub Actions의 `Reader Translation Release Quality` 수동 워크플로로 엄격한 사람 평가 게이트를 별도 실행할 수 있다. 기본 source-light 검사는 코드와 데이터 구조를 확인하고, 이 워크플로는 `--require-passing`으로 저장된 사람 평가의 미달 또는 미완료 상태를 차단한다. 워크플로는 모델을 호출하거나 평가 점수를 바꾸지 않는다. 당시 니체의 미달 판정은 아래 재평가 전까지 유지했다.

## 2026-09-09 실제 모델 검증과 표본 확장

`data/translation_quality_sample_plan.json`에 원문 문장 16개를 모델 생성 전에 고정했다. 코퍼스마다 4건씩 추가했으며 성경의 히브리어·그리스어, 키르케고르의 철학 본문·강화, 니체의 시구·비유·논증, 비트겐슈타인의 독일어·영어 본문을 포함한다. 짧은 금지문, 재귀 표현, 긴 복문, 개념 열거, 원고 이형 표기를 분산해 선정했다. 목적 표집이므로 전체 코퍼스나 시대별 분포의 통계적 대표성을 주장하지 않는다. 기존 승인·회귀 문장에 근접한 문맥도 포함되어 있어 독립적인 미학습 평가 집합으로 취급하지 않는다.

실행 결과는 [실제 모델 검증 보고서](translation_live_validation_20260909.md)에 기록했다. 새 후보는 자동 비평 12건 통과, 4건 사람 검토 필요로 남았으며 이 수치는 사람 합격률이 아니다. 생성 직후 모든 새 항목의 점수·평가자·확정 번역은 비워 두었고, 기존 4건과 평가 이력은 그대로 보존했다.

미평가 항목이 있으면 `--require-complete`와 `--require-passing`이 실패한다. 평가가 끝나더라도 한 차원 이상 미달이면 `--require-passing`은 계속 차단한다. 기존 네 항목의 합격을 이유로 새 표본을 릴리스 게이트에서 제외하지 않는다.

원문 문맥, 모델 원본, 비평 이력과 모델 식별 정보는 Git 제외 디렉터리 `data/runtime.local/translation-validation-20260909/`에 보관한다. 골드셋에는 공개 정책이 허용하는 문장 단위 원문·후보·평가 상태를 추가한다. 후보 UUID는 이 검증 디렉터리의 `ai/` 기록과 연결된다. 운영에 사람 확정본을 반영할 때는 정확한 판본·문장·원문 해시 및 해당 모델 원본을 다시 확인한다.

평가 자료는 코퍼스마다 4건으로 나눴다. 각 항목에는 평가 대상 원문, 후보, 실제 모델에 제공한 주변 문맥, 원문 링크, 답변 칸이 있다. 자동 비평·모델 해설은 평가 문서에서 제외했다. 사람이 충실성/완전성/용어/가독성 점수, 확정 번역, 판정 근거를 제출한 뒤에만 해당 항목을 `evaluated`로 전환한다. 보류는 `pending`으로 유지한다. `evaluated_at`은 평가 답변을 수신해 기록한 시각이며, 별도의 평가 수행 시각이 제공되면 이를 따른다.

- [성경 B01–B04](../data/runtime.local/translation-validation-20260909/review-bible.md)
- [키르케고르 K01–K04](../data/runtime.local/translation-validation-20260909/review-kierkegaard.md)
- [니체 N01–N04](../data/runtime.local/translation-validation-20260909/review-nietzsche.md)
- [비트겐슈타인 W01–W04](../data/runtime.local/translation-validation-20260909/review-wittgenstein.md)

평가 답변은 `human-<corpus>.json`에 저장하고, 점수·확정 번역·근거를 골드셋에 반영한다. 모델의 `translation`은 바꾸지 않고 사람 확정문을 `human_translation`으로 연결한다. `후보와 동일`이라는 답변은 해당 평가 문서의 정확한 후보 문자열로 해석한다.

키르케고르 K02처럼 모델 후보가 미달이어도 평가자가 별도의 확정 번역을 제출할 수 있다. 그 교정문은 운영에서 제공하되, 골드셋의 후보·점수·미달 판정은 유지한다. 사람 교정문을 모델이 생성한 것처럼 기록하거나 교정문에 기존 후보의 점수를 자동으로 옮기지 않는다. 새 모델 후보가 합격했는지는 별도의 재평가로 확인한다.

확장 표본 16건의 사람 평가를 모두 반영했고 각 확정문을 운영 기록의 `human_translation`으로 연결했다. 기존 4건과 모델 원본은 보존했다. 당시 `--require-complete`는 통과했지만 `--require-passing`은 세 미달 후보 때문에 차단됐다. 자동 비평이 통과시킨 K02·W03도 당시 사람 판정에 따라 미달로 유지했다. 후속 v8 재평가의 최신 결과는 아래 기록을 따른다.

실제 모델 검증을 다시 수행하려면 Reader 데이터와 공유 로컬 모델이 준비된 상태에서 **새 출력 디렉터리**를 지정한다. 기본 CI에 연결하지 않았으며 이 명령은 실제 추론 자원을 사용한다.

```powershell
python -X utf8 .\scripts\check_translation_live.py --output-dir .\data\runtime.local\translation-validation-new-run --validate-plan-only
python -X utf8 .\scripts\check_translation_live.py --output-dir .\data\runtime.local\translation-validation-new-run
python -X utf8 .\scripts\check_translation_live.py --output-dir .\data\runtime.local\translation-generation-new-run --generation-only --case-id K02 --case-id N01 --case-id W03
python -X utf8 .\scripts\check_translation_quality_regressions.py --with-model
```

검증 스크립트는 기존 `server.Handler`로 임시 루프백 HTTP 서버를 열고 실제 원문 해석·번역·저장 경로를 호출한다. 모델 응답을 대체하지 않으며 HTTP 호출 시각만 관측한다. 저장 경로는 해당 검사 프로세스에서만 별도 디렉터리로 바꾼다. 운영 Reader·공유 모델의 시작/종료나 장애복구 설정을 변경하지 않는다. 새 실행의 후보는 실행 디렉터리에만 생성되고 골드셋 후보나 기존 사람 점수를 자동으로 교체하지 않는다.

## 사람 평가 입력 검사와 반영 명령

`scripts/apply_translation_human_review.py`는 사람이 제출한 JSON 평가를 후보 UUID와 실제 원문에 대조한다. 기본 실행은 dry-run이며 파일·잠금 보조파일·백업을 만들지 않는다. `--apply`를 명시해야 운영 AI 기록과 골드셋에 반영한다. 새 모델을 호출하거나 승인 규칙을 자동 작성하지 않으며 후보의 `ai/` 원본과 검토 문서는 읽기만 한다.

평가 JSON은 `schema_version: 1`, `evaluator`, 시간대가 있는 `evaluated_at`, `cases`를 가진다. 각 항목은 `id`, 검토 자료의 정확한 `candidate_record_id`, 네 차원 이름으로 된 `scores`, `reference_translation`, `notes`를 가진다. 선택 항목 `sample_label`과 `score_order`는 제공할 경우 후보 및 충실성·완전성·용어·가독성 순서와 일치해야 한다. 점수는 1~5 정수로 입력하며 보류 항목은 이 파일에 포함하지 않는다. “후보와 동일”은 입력 전에 정확한 후보 문자열로 확정한다. 기존 골드셋에 있는 항목의 재평가·교정 반영만 지원하며 새 표본 추가는 별도의 표집 절차를 따른다.

Reader 디렉터리에서 현재 LSHD 입력을 다시 검사하는 예시는 다음과 같다. 이미 반영된 이 입력은 `status: no_op`, `changed_files: 0`이며 시간 필드도 바꾸지 않는다.

```powershell
python -B -X utf8 .\scripts\apply_translation_human_review.py --feedback .\data\runtime.local\quality-followup-20260930-v8-final\human-LSHD-v8-20260930.json --candidates .\data\runtime.local\quality-followup-20260930-v8-final\candidates.json
```

새 사람 평가를 검증한 뒤 같은 명령 끝에 `--apply`를 붙여 반영한다. 후보 기록은 기본으로 `candidates.json` 옆 `ai/`에서 찾고, 다른 곳이면 `--candidate-ai-dir`로 지정한다. 운영 대상은 `PHILO_AI_DIR` 또는 `data/ai`이며 `--ai-dir`, `--goldset`으로 별도 합성 검사 대상을 지정할 수 있다. UUID, 판본·문장 식별자, 원문·문장 해시, 모델 원본, 점수와 공개 골드셋 제한이 맞지 않으면 반영을 중단한다. 더 최신인 사람 평가나 수동 확정문을 오래된 입력으로 덮지 않는다.

변경 전 파일은 기본 `data/runtime.local/human-review-imports/backup-<UUID>/`에 보존하며 원본·변경 후 SHA-256와 상태를 저널에 기록한다. 프로젝트 안에서는 `--transaction-dir`가 반드시 `data/runtime.local` 아래여야 한다. 프로젝트 밖에 직접 지정한 백업 디렉터리도 원문·모델·개인 기록을 담으므로 비공개로 관리한다. 콘솔에는 건수·상태만 출력한다. 기존 모델 출력은 보존하고 사람 확정문만 연결하며 미달 점수를 합격으로 바꾸지 않는다. 새 후보 UUID로 바꿀 때는 골드셋 이전 후보·평가를, 같은 운영 기록을 재평가할 때는 이전 사람 평가를 이력에 보존한다. 변경하지 않는 AI 기록의 줄은 바이트 그대로 유지한다.

커밋 전에 실패하면 백업으로 복구한다. 디스크에 커밋 마커가 게시된 뒤 예외가 발생하면 변경 후 해시를 검증하고 `import_failed_committed`로 이미 반영된 상태를 알린다. 강제 종료로 `pending/`이 남으면 기본 dry-run은 쓰지 않고 중단하며 **원래 입력과 경로로 `--apply`를 재실행**해 복구·커밋 상태 확인 후 다시 반영한다. 이미 반영됐으면 재실행은 `no_op`다. 목표 파일이 저널의 변경 전·후 해시 중 어느 것과도 일치하지 않으면 외부 변경으로 판단해 파일과 저널을 보존하고 중단한다. 다른 평가 입력으로 미완료 저널을 대신 적용하지 않는다. 로컬 도구의 잠금을 따르지 않는 외부 편집·복사와 동시에 실행하지 않는다. 백업은 성공 또는 복구 후에도 삭제하지 않으며 필요한 보존 기간을 확인한 뒤 관리한다. 실제 정전 내구성은 여기서 검증하지 않았다.

## 5영역 제출 평가 장부

`apply_translation_human_review.py --review-store <비공개 JSON 경로>`는 번역과 번역 노트의 5영역 제출 평가를 별도 장부에 반영한다. 기존 `schema_version: 1`의 4영역 골드셋·운영 반영 명령은 그대로 사용한다. 수집 모드의 `--apply`는 지정한 평가 장부만 저장하며 운영 번역, 개인 노트, 기존 골드셋이나 승인 규칙을 변경하지 않는다. 수집은 `--goldset`, `--ai-dir`과 함께 사용할 수 없다. 프로젝트 안의 장부와 복구 디렉터리는 `data/runtime.local` 아래에 둔다.

입력은 `schema_version: 2`, `score_order`, `cases`를 가진다. 점수 순서는 `omission_addition`, `logic`, `terminology`, `korean_readability`, `note_accuracy`다. 항목별로 `id`, `candidate_record_id`, `sentence_text_sha256`, `candidate_translation_sha256`, `decision`, `evaluator`, `evaluator_kind`, `evaluated_date`, `scores`, `reference_translation`, `note_action`, `translation_notes`, `notes`를 제공한다. 후보 입력은 50문항 생성 도구의 `candidates.json` 형식이며 원본 모델 기록은 기본으로 그 옆 `records/`에서 읽는다.

앞의 네 점수는 1~5 정수다. `note_accuracy`는 모델 후보의 공개 가능한 노트에 대한 점수이며, 해당 노트가 없으면 `null`을 유지한다. 새로 채택할 노트도 없으면 `note_action: "not_applicable"`을 사용한다. 모델 노트가 없더라도 별도로 작성한 보완 노트를 채택할 때에는 점수를 `null`로 둔 채 `replace`를 지정할 수 있다. 모델 노트가 있으면 정수 점수와 `keep` 또는 `replace`를 지정한다. `replace`는 정확한 원문 부분 문자열을 인용한 `{source_span, note}` 목록을 최대 3개 제공한다. 저장하는 노트는 확정문의 해시와 원문 해시에 연결한다. 모델의 번역·노트·생성 기록은 읽기만 한다. 이 처리 구별은 기존 schema 2 필드를 사용하며 모델에 없던 노트의 점수를 만들어 내지 않는다.

`decision: "confirmed"`는 제출 파일에서 확정한 문구를 뜻하며 독립적인 사람 평가나 운영 채택을 자동으로 뜻하지 않는다. `decision: "held"`는 빈 `reference_translation`과 `provisional_translation`을 함께 제공한다. 보류 점수와 잠정 노트도 기록하지만 확정문에 대한 노트 연결은 만들지 않는다. `evaluator_kind`는 `unspecified`, `ai`, `ai_assisted` 중 하나이며 평가자 문자열을 함께 보존한다. 파일의 평가일은 `YYYY-MM-DD`로 저장한다. 정확한 시각을 받았을 때만 시간대가 있는 `evaluated_at`을 추가하며 시각을 추정하지 않는다.

기본 실행은 파일과 잠금 파일을 만들지 않는 dry-run이다. UUID·현재 원문·원본 모델 기록·번역 해시·노트 유무를 검증한다. `--apply`도 잘못된 입력은 쓰기 잠금 파일을 만들기 전에 거부하고, 실제 저장 직전에 잠금 안에서 다시 검사한다. 변경 전 장부와 변경 후 내용을 기존 트랜잭션 방식으로 백업한다. 같은 입력을 다시 반영하면 `no_op`다. 재평가 시 이전 평가와 노트 연결을 이력에 남기며, 오래된 날짜와 순서를 확인할 수 없는 같은 날의 변경을 거부한다. 같은 날 다른 평가를 반영하려면 양쪽의 정확한 시각이 있어야 한다. 미완료 트랜잭션은 원래 입력으로 `--apply`를 재실행해 복구한다.

Reader 디렉터리에서 다음처럼 검증한다. 실제 저장은 검증된 동일 명령 끝에 `--apply`를 붙인다.

```powershell
python -B -X utf8 .\scripts\apply_translation_human_review.py --feedback .\data\runtime.local\review-tool-v2-20261002\feedback-v2.json --candidates .\data\runtime.local\notes-benchmark-20261001-170014\candidates.json --review-store .\data\runtime.local\review-tool-v2-20261002\evaluation-store.json --transaction-dir .\data\runtime.local\review-tool-v2-20261002\transactions
```

고정 50문항 계획의 원문과 이전 평가 데이터는 재작성하지 않는다. 새 장부는 UUID별 제출 평가·교정문·노트와 보류 상태를 보관하는 별도 스키마다. 확정문을 Reader에 게시하는 작업과 기존 승인 규칙 충돌 해결은 이 장부 반영과 별도로 진행한다.

### 명시적으로 채택한 항목을 Reader에 반영

장부의 `confirmed`만으로 운영 반영하지 않는다. 사용자가 채택한 항목에 한해 `--review-store`, `--publish-case <ID>`, `--candidate-ai-dir`, `--approved-by`, `--adopted-at <시간대 있는 실제 처리 시각>`을 지정하고 별도 dry-run 후 `--apply`한다. 여러 항목은 `--publish-case`를 반복하며 보류 항목은 거부한다. 이 모드는 `--feedback`, `--candidates`, `--goldset`과 함께 쓰지 않는다. `--ai-dir`은 운영 목적지를 지정한다.

기존 모델 출력과 노트를 보존하고 `human_translation`, 선택적 `human_evaluation_v2`, `human_translation_notes`를 추가한다. 평가는 원래 후보 UUID·원문·모델 번역 해시에 연결하고 노트는 채택한 번역과 원문에 연결한다. 평가일만 받은 경우 `evaluated_at`은 비워 두며 실제 반영 시각을 `reviewed_at` 등에 따로 기록한다. 새 원문과 이전 잘린 원문의 평가는 별도 항목으로 유지한다. Reader 응답은 검증된 노트를 표시하고 새 평가의 전체 근거와 내부 연결 정보는 포함하지 않는다.

동일 채택을 반복하면 `no_op`이며, Reader에서 이후 직접 수정한 내용을 재제출로 덮어쓰지 않는다. 번역이나 원문이 노트의 연결과 달라지면 노트를 숨긴다. 재평가 이력, 대상 파일 백업, 원래 입력으로의 중단 복구는 수집 모드와 같은 검증을 적용한다.

## 2026년 10월 2일 문장 경계와 승인 규칙 충돌 수정

R23의 `ɔ:`는 설명 약호인데 콜론 뒤를 문장 끝으로 분리하고 있었다. 약호 뒤를 연결하여 `sks-0034.s001`의 괄호 설명까지 복구한다. 원문 세그먼트는 편집하지 않는다. 합쳐진 `.s002`는 `.s001`로 연결되는 별칭으로 남기며, 뒤 문장의 기존 ID도 유지한다. [Tekstnet의 해당 문단](https://tekstnet.dk/books/kierkegaard-s_begrebet-angest/006/)에도 이 설명이 같은 괄호 안에 있다. 복구된 문장의 SHA-256는 달라지므로 짧았던 원문에 매긴 점수·잠정안과 새 문장의 평가를 구분한다. 이전 50문항 원문 계획과 제출 장부는 그대로 보관하고 복구된 문장은 새 검토 대상으로 준비한다.

R28의 `미지`와 `알지 못한다`는 이 문맥의 승인된 동의 표현으로 함께 검사한다. 용어의 원래 `target`은 유지하고 선택적인 `alternatives` 목록을 추가한다. 주어·술어 관계 검사와 핵심 술어 누락·오접속의 거부 규칙은 유지한다. 새 확정문과 기존 확정문이 모두 통과하고, 핵심 술어가 없는 문장은 계속 거부되어야 한다.

[WAB의 교정 전사](https://wab.uib.no/sample/201a-1.htm)는 `these`의 `e`를 `o`로 교정한 흔적을 보여 준다. R41의 읽기용 번역에서는 교정 후 독법을 허용하고 기존 `이 || 저` 전사 보존 번역도 유지한다. 출력에 `||`를 사용한 경우에만 양쪽 요소를 요구하는 `when_translation_contains` 조건을 추가한다. 잘못 놓인 구분자와 `only`의 한정 범위가 바뀐 문장은 계속 거부한다. `속박변수`도 허용하며 기존 `겉보기 변수`·`외견상 변수`·`외견적 변수`를 오역으로 바꾸지 않는다. [Principia Mathematica의 설명](https://www.gutenberg.org/files/78050/78050-src/78050-src.htm)에서도 apparent variable은 양화된 변수의 쓰임으로 소개된다.

[출애굽기 8장 주석](https://classic.net.bible.org/bible.php?book=Exo&chapter=8), [ODS hæve 5.1](https://ny.ordnet.dk/ods/ordbog/h%C3%A6ve), [Blue Book](https://wittgensteinproject.org/w/index.php/Blue_Book), [니체 §§35–38](https://www.gutenberg.org/cache/epub/7207/pg7207-images.html)을 대조했다. `note_checks`는 문장·원문 SHA-256에 한정해 확인된 잘못된 설명 전체를 공백 정규화 후 비교한다. 7건의 기존 잘못된 설명은 비평이 통과시켜도 재검토로 전환되며, API·Reader·번역 목록·Markdown에서는 노출을 보류한다. 원래 저장된 설명과 사람의 수정 노트는 보존한다. 이것은 이미 관찰한 설명의 재발 검사이며 임의의 바꿔 쓴 설명을 모두 판정하는 의미 검증기가 아니다. 문법 용어의 단순 언급이나 이를 부정하는 올바른 설명을 금지하지 않는다.

## 2026년 10월 3일 비평의 의미·가독성 구별 보완

R37·R44·R47에만 원문 해시로 한정한 대조 설명을 추가했다.
