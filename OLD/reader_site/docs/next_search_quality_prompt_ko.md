# 다음 작업 프롬프트: 검색 품질 평가와 근거 기반 랭킹 보정

아래 프롬프트는 Personal Archive of Literature 프로젝트의 다음 검색 품질 작업을 다른 Codex 작업이나 외부 검증자에게 그대로 전달할 수 있도록 작성되었다.

```text
당신은 Personal Archive of Literature 로컬 리더의 검색 품질 개선 담당자다.

목표
- 실제 저장된 네 코퍼스와 기존 검색 평가 사례를 기준으로 검색 품질을 측정한다.
- 실패하거나 약한 사례가 확인될 때만 일반화 가능한 최소 랭킹 수정을 적용한다.
- 검색 평가를 재현 가능한 데이터와 수치로 남긴다.

필수 입력
- reader_site/services/search.py
- reader_site/data/search_eval_queries.json
- reader_site/scripts/check_search_relevance.py
- reader_site/scripts/check_search_contracts.py
- reader_site/data/*_metadata.json
- reader_site/data/search_index.sqlite
- reader_site/docs/codebase_review_2026-07-30.md

작업 절차
1. Git 작업 트리와 기존 사용자 변경을 확인하고 보존한다.
2. 기존 평가 사례를 먼저 실행해 기준선을 기록한다.
3. 평가 파일의 ID 중복, 필수 필드, 기대 순위 범위를 검증한다.
4. 네 코퍼스의 실제 메타데이터·본문·일상 연구 흐름에서 대표 질의를 추가한다.
   - 작품 약칭과 전체 제목
   - 성경 직접 참조와 소스 접두사
   - 원문 핵심어와 다단어 구문
   - corpus/work/variant 필터
5. 각 사례의 기대 결과 순위로 MRR과 Recall@k를 계산해 사람이 읽을 수 있는 요약과 JSON 출력을 지원한다.
6. 새 사례에서 실패가 확인되면 특정 질의 문자열을 하드코딩하지 말고, 별칭 정규화·구문 일치·필터·일반 랭킹 신호 중 원인에 맞는 최소 수정을 한다.
7. SQLite FTS5 경로와 JSONL fallback의 공통 점수 계약을 훼손하지 않는다.
8. 검색어를 자동 수집하거나 사용자 질의를 로그로 저장하지 않는다.
9. 검색, API, 레이아웃, 정적 라우트, 릴리스 계약과 git diff 검사를 실행한다.

성공 기준
- 기존 평가 사례가 모두 유지된다.
- 평가 데이터가 네 코퍼스와 주요 검색 유형을 더 넓게 포함한다.
- 평가 스크립트가 사례 수, 통과 수, MRR, Recall@1/3/10을 보고한다.
- 새 평가 사례가 모두 통과하거나, 통과하지 못한 사례와 원인이 명시적으로 기록된다.
- 검색 결과 형식과 공개 API 계약에 회귀가 없다.
- 릴리스 분류 결과가 block 0, review 0이다.

제약
- 소스 코퍼스, 생성 검색 DB, 개인 노트, 로컬 AI 기록을 수정하지 않는다.
- 새 운영 의존성을 추가하지 않는다.
- 증거 없는 대규모 가중치 조정이나 프런트엔드 재설계를 하지 않는다.
- 커밋, 푸시, 배포는 별도 요청이 없으면 수행하지 않는다.

최종 보고
- 추가한 평가 사례와 근거
- 기준선과 개선 후 지표
- 변경한 랭킹 규칙과 일반화 근거
- 실행한 검증과 미검증 항목
- 남은 검색 품질 리스크
```
